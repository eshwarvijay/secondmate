## 2026-09-08 — doctor-plugin-update: bin/doctor.sh detects and heals a stale secondmate plugin install

- **Trigger:** user request — `doctor.sh --heal` should detect when the running secondmate plugin is stale relative to the marketplace checkout and heal it (pull + `claude plugin update`), distinguishing genuine staleness from "silent drift" (new commits, no version bump — healing can't help) and "reload pending" (already healed on disk, session just needs `/reload-plugins`). Full plan committee run (adhd + 6-model plan-committee.sh) per explicit user instruction for this task.
- **Maker path:** pi (Qwen3-Coder-Next, medium thinking), dedicated worktree workspace `w1N`, root pane `w1N:p1`, restarted fresh (new pi process on the same pane) at the start of nearly every round — a deliberate pattern that converged far more reliably and cheaply than continuing in a single long-running, increasingly degraded context.
- **Worktree:** `herdr worktree create` → `sm/doctor-plugin-update`
- **Rounds:** an unusually long task — roughly 18 maker rounds and 10 checker rounds across two merge attempts (the first merge had to be unwound after exposing a real bug; see below). Selected highlights:
  - **Round 1 (combined, discarded):** the very first attempt combined "redesign the state machine" + "build a full mock-marketplace selfcheck harness" into one ask; the maker's context degraded badly (repeated text-duplication editor mistakes, 80%+ context usage), and in the process **corrupted the repo's own real `.claude-plugin/plugin.json`**, overwriting it with a test-fixture stub. Caught before commit; worktree reset to the last clean commit; the combined round was abandoned in favor of narrowly-scoped sequential rounds (state-machine fix only, then selfcheck coverage only, then heal-path coverage only) — this scoping discipline converged far more cheaply for the remainder of the task.
  - **Checker round 1 (fail, 3 CONFIRMED bugs):** (1) the state-machine's stale-vs-silent_drift comparison used `running_version` (this script's own version) instead of `installed_version` (from `installed_plugins.json`) as the reference point — a real version bump running from a location whose own version coincidentally matched the marketplace's would misreport a genuine, healable update as unhealable "silent drift"; (2) heal verification only checked `after_sha != local_sha` (changed at all), accepting ANY wrong SHA as a successful heal; (3) `_acquire_heal_lock`'s stale-lock-steal logic was unreachable for a lock that already existed at function entry (the realistic crashed-process case), only reachable via a vanishingly narrow TOCTOU race.
  - **Checker round 2 (fail, 2 CONFIRMED bugs):** (4) a failed heal was reported as script success — `heal()`'s captured `heal_result` was never checked, and even if it had been, the script's own final exit-code line was unconditional and unrelated to heal outcome; (5) the round-1 lock fix's stale-lock-steal was a genuine TOCTOU race the checker's own orchestrated probe actually demonstrated (process A's delayed `rm -rf`, based on a stale decision, destroyed process B's already-replaced fresh lock) — closed with an atomic `mv`-based claim (only one process's `mv` from a given source can ever succeed) plus a post-claim re-verification, rather than another narrowing re-check.
  - **Checker rounds 3-6 (fail each, 1 CONFIRMED bug each, same recurring pattern):** a single underlying bug class — "optimistic reporting on unverifiable/hard-abort state" — surfaced independently 4 more times across 4 different functions: the report table showing `[ok]`/plain "STATUS: ready" for a genuinely `stale` row (only `MISSING` was ever counted toward the summary line); the same gap for `UNKNOWN` (malformed `installed_plugins.json`); `heal()` never even dispatching to `_heal_secondmate` for a `missing` marketplace checkout at all (so the spec's required hard-abort silently never fired); and the same STATUS-line gap recurring a 3rd time specifically for the missing-marketplace row. Each was found by a different checker round on a different code path, each independently reproduced by the supervisor with a from-scratch fixture before being trusted.
  - **Checker round 7 (fail, 2 test-coverage-only findings):** two already-correct hard-abort paths (`git fetch` failure, `claude plugin update` failure) had never actually been exercised by a dedicated regression test — the supervisor verified both behaviors were already correct via real fixtures before authorizing test-only additions.
  - **Checker round 8: PASS.** First genuine pass after 7 failing rounds.
  - **First merge, then unwound:** merged to main, bumped `plugin.json`'s version (0.1.8 → 0.1.9) per this repo's standing per-merge convention — this immediately broke `bin/doctor.sh --selfcheck` on the actual merged main. Five selfcheck tests had hardcoded the literal `"0.1.8"` to represent "the currently running script's own version," which coincidentally worked for the entire rest of the task only because this worktree's own `plugin.json` never itself changed version across 18 rounds. Nothing had been pushed yet, so the merge was cleanly unwound (`git reset --hard`) rather than fixed forward on main.
  - **Checker round 9 (fail, 1 CONFIRMED bug):** the fix for the above (replacing hardcoded `"0.1.8"` with the live `$version_line`) correctly closed the 5 broken tests, but a caught-and-fixed intermediate commit had also accidentally stripped the real `.claude-plugin/plugin.json` manifest down to a bare `{name, version}`, and separately, Test 4's own "must differ from running version" literal (hardcoded `"0.1.7"`) was itself a second instance of the exact same collision class one level deeper.
  - **Checker round 10: PASS**, with one `[SUSPECTED]` (not confirmed, checker could not reproduce it) note: selfcheck's synthetic dead-PID lock fixtures use large hardcoded PID numbers that could theoretically, extremely rarely, collide with a coincidentally-live unrelated process — accepted as a documented limitation, the same class of narrow PID/TOCTOU risk already tolerated elsewhere in this codebase (e.g. `caffeinate-guard.sh`).
  - **Real process-hygiene bug, unrelated to any specific checker finding:** an early-round test (`Test F1`, live-PID fixture for the lock-liveness check) spawned a real background `sleep 300` process and never killed it on any exit path. Every single `--selfcheck` invocation since that test was added leaked a 5-minute orphaned process that inherited open file descriptors — explaining a long string of apparent multi-minute "hangs" throughout this task that were never actually hangs in `doctor.sh` itself, only hangs in whatever downstream command happened to pipe its output through something waiting for EOF (e.g. `| tail`). Diagnosed by the supervisor directly via `ps aux`/`lsof` while a maker's own piped invocation sat blocked; fixed by explicitly killing the spawned process immediately after the one assertion that needs it alive.
  - **Repeated maker process failures this task (both self-recovered by the supervisor):** (a) the maker replied "DONE" with real, uncommitted work still in the tree on at least 3 separate occasions across different rounds, caught each time by the supervisor independently checking `git status`/`git diff HEAD` rather than trusting the reply; (b) the maker got stuck in a genuine repeated-retry loop against `scope-guard`'s path confinement, attempting the identical blocked `python3 /tmp/<script>.py` invocation many times in a row without adapting, burning real cost (~$4 in one instance) with zero progress — resolved each time by having the maker use its own edit tool directly on `bin/doctor.sh` instead of any external script file, and once by the supervisor handing over exact verbatim code for the maker to insert (matching the `doctor-version-flag` precedent) after a second stuck-loop recurrence.
- **Outcome:** verify-gate PASS at `e652c20` (checked-sha match, second attempt) → human hold answered `merge` (fresh per-task approval, both before and after the mid-task unwind) → merged to main `--no-ff` at `91b7880` (one trivial `plugin.json` version-conflict, hand-resolved to `0.1.9`) → full repo-wide selfcheck chain re-run clean on the actual merged commit → pushed → worktree/branch/pane torn down.
- **Lesson:** this task's single most valuable recurring discipline was independently reproducing every checker finding with a from-scratch fixture (never reusing the maker's own test code) before writing the next fix instruction, and independently mutation-testing every new/changed selfcheck assertion (revert the fix, confirm the test fails, restore) before trusting it — this caught, among other things, a maker's DONE summary that factually misdescribed what was actually in its own `git diff`, and a "fixed" test that provably didn't exercise the real code path it claimed to guard. The other major lesson: a feature's own selfcheck can pass every single round of a long task and still be lying about being version-agnostic, if the one thing that's supposed to vary (the plugin's own version number) never actually varies within the dev environment where all that testing happens — the bug was only exposed by the very act of merging and bumping the version for real.
