## 2026-09-07 — caffeinate-guard: macOS sleep-prevention guard for maker/checker batches

- **Trigger:** explicit user instruction — the supervisor should start `caffeinate` when a batch of tasks begins and reliably stop it once every worktree finishes, as an actual plugin feature (not something the supervisor just remembers to do manually, which was the prior session's ad-hoc approach).
- **Planning:** full plan committee run (adhd 5-frame divergent ideation + 6-model plan-committee.sh) on the ORIGINAL per-task-id design. Multiple independent frames converged on the same three ideas (identity-verified kill over trusting exit codes, a bounded `-t` dead-man's-switch, per-task isolation via `setsid`) — a strong signal later validated by the checker's own findings.
- **Maker path:** pi (Qwen3-Coder-Next, medium thinking), dedicated worktree workspace `w1H`.
- **Design pivot (mid-task, user-directed):** the original per-task-id mkdir-lock design accumulated narrowing races across 4 checker rounds that never converged (the classic symptom already seen once before in this repo on the Bash-heuristic scope-guard). The human first asked for the *locking primitive itself* to be redesigned (a plan-committee round was launched for this), then, before that redesign finished, proposed a fundamentally simpler architecture: since the supervisor is a single sequential caller (never truly concurrent with itself), per-task-id locking was solving a problem that doesn't exist — one session-scoped singleton guard is sufficient. The in-flight redesign work was discarded; the maker was redirected to the simpler design (net deletion: 99 insertions / 303 deletions in that pivot commit).
- **Rounds:** 12 checker rounds on the simplified design (plus ~6 on the abandoned per-task-id generation before the pivot). Real, fixed findings: a discarded custom `--ttl` value (variable-shadowing bug); a documentation-wiring bug where `stop` sat inside each task's *per-task* Teardown step, which would kill the shared guard when the first of several concurrent tasks finished; a genuine concurrent-`start` orphan-leak (fixed with a short-lived atomic noclobber claim, not a return to per-task locking); a command-substitution hang (the backgrounded `caffeinate` process inheriting the caller's stdout pipe — `result=$(...)` would hang for the full 8-hour TTL); a stale-lock deadlock and a genuinely-alive-holder infinite hang (both in the abandoned per-task-lock generation, fixed there before the pivot); a strict-argument-parsing gap in `stop`; and — the largest single time sink of the task — a cluster of `set -e`/`pipefail` bash pitfalls (a legitimate zero-match `grep` killing the whole selfcheck under `pipefail`; a bare command's exit code checked on a separate, unreachable line) plus a genuinely bizarre test-environment artifact: this machine's shell has a custom `grep` function wrapping `ugrep`, and the spawned `ugrep` subprocess exposes the *unbracketed* search text in its own `ps aux` argv, defeating the standard `[c]affeinate` self-exclusion idiom used throughout the file — fixed by abandoning text-pattern process searching for that specific check and checking a directly-captured, known PID instead.
- **Accepted limitations (documented in the script's own header, not chased further, each a supervisor scope decision):** (1) this is a single host-wide guard — two independent secondmate-orchestrating sessions on the same machine share it, so one session's teardown can end another's still-active sleep prevention; (2) a `start`/`stop` overlap for the same guard requires both violating the documented call-ordering contract (`stop` only after every task/worktree in the batch is torn down) *and* an artificially-held-open timing window (the checker's own repro used a wrapped `rm` to force it) to reach; (3) the identity-fingerprint check assumes `caffeinate` in PATH is the real, well-behaved system utility, not an adversarially-substituted decoy that replaces its own process image via `exec` after launch — a PATH/supply-chain threat model outside this convenience feature's scope. All three share the same worst-case blast radius already bounded by the TTL ceiling: one orphaned but self-expiring process, never a permanent leak.
- **Outcome:** verify-gate PASS at `10d6178` (checked-sha match) → human hold answered `merge` (a genuine per-task ask this time, not standing batch authorization, since this task started fresh in a new conversation) → merged to main `--no-ff`, clean, no conflicts → full repo-wide selfcheck chain re-run on the actual merged commit → pushed → worktree/branch/workspace torn down.
- **Lesson:** the single biggest time sink of this entire task (many rounds) was never the caffeinate-guard *logic* — it was verifying the *tests* themselves, repeatedly running into `set -e`/`pipefail` interactions that silently killed the selfcheck with zero diagnostic output, and a machine-specific shell customization that broke a self-exclusion idiom used throughout the file. Supervisor discipline that actually converged this: independently reproducing every failure in isolation with `bash -x` tracing before sending another instruction to the maker, rather than letting the maker's own context-degrading trial-and-error compound round after round.
