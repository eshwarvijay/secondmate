## 2026-09-24 — lesson-store: turn hardcoded "Known failure patterns" into a retrievable lesson store

- **Trigger:** direct follow-up to a starred-repo research pass the coordinator commissioned earlier in the same session (`docs/STEAL-LIST.md`, commit `d8fa442`) — item #1 on that list, MisakaNet's git-backed lesson library pattern (BM25-style retrieval, evidence levels E0-E4), adapted to close a gap that list itself named: `skills/secondmate/SKILL.md` pastes the identical 4-bullet "Known failure patterns" block verbatim into 7 separate maker-prompt sites, manually curated, growing monotonically, injected regardless of task relevance.
- **Maker path:** pi (Qwen3-Coder-Next, medium thinking), dedicated worktree workspace `w3R`, root pane `w3R:p1`. Task run entirely by a fork given full supervisor ownership (spawned by the coordinator specifically to free it up for other concurrent work; ran the complete plan-committee → maker → checker → gate → hold → merge → audit → teardown sequence autonomously).
- **Worktree:** `herdr worktree create` → `sm/lesson-store`.
- **Planner committee:** ran unconditionally (6 pi planners). The single most important finding, independently flagged by multiple planners (most sharply by `kimi-k3`'s integration-risk review): with only 4 seed lessons, a naive "always return top 3" cap would silently drop one proven lesson on day one, before the store had grown at all — a pure regression hidden inside an otherwise spec-compliant implementation. Resolved by giving the `evidence` tier real semantic weight rather than treating it as decorative metadata: every `evidence: E4` lesson is unconditionally included regardless of relevance score; only non-E4 lessons get filtered/capped. Today, with exactly 4 E4 seeds and nothing else, this means zero regression — all 4 always appear. A second `kimi-k3` finding (no fallback if the script itself fails for any reason — missing directory, permission error, any exception — would silently substitute an EMPTY block into the maker prompt, worse than the static status quo) was resolved by wrapping the real logic in a try/except with the original 4 lessons hardcoded as a literal last-resort fallback inside the script itself, independent of any file read. Noise discarded: bash-only implementation concerns from two planners (frontmatter parsing/tokenization in bash was independently flagged as fragile by both `qwen3-coder` and `mistral-large3` — resolved by using Python instead, matching this repo's own existing convention for text-processing-heavy `bin/` tools); a large security-theater section from `mistral-large3` (OS command injection / path traversal via `--task`, inapplicable since the task string is never passed to a shell or used to construct a file path).
- **Rounds:** 5 total — 2 maker fix rounds before any checker involvement (both driven by the fork's own direct testing, matching this session's established discipline), then 3 real checker rounds (`gpt`, `qa/coverage` + `qa/test-reality` lenses), each finding genuine, independently-reproduced bugs:
  1. **(fork-found, pre-checker):** all 7 of the newly-wired `skills/secondmate/SKILL.md` command substitutions were missing the inner `$` before `{CLAUDE_PLUGIN_ROOT}` — `$({CLAUDE_PLUGIN_ROOT}/...)` instead of `$(${CLAUDE_PLUGIN_ROOT}/...)`. The fork independently executed the exact broken fragment and confirmed it causes an outright bash parse error (not just empty output) — every one of the 7 wired maker-launch commands would have failed to even parse. Fixed in all 7 places; the fork re-executed the corrected substitution end-to-end and confirmed it printed all 4 real seed lessons correctly.
  2. **(checker round 1):** `parse_frontmatter()` silently discarded ALL tags for every real shipped lesson file — the multi-line YAML list form (`tags:\n  - value\n  - value`, the format all 4 real seed files actually use) was never handled; a bare `tags:` line set `tags=[]` and subsequent dash-prefixed lines were skipped entirely (no colon on those lines to satisfy the line-parser's own gate). The fork independently reproduced this on the real `commit-before-done.md` file (`{'tags': [], ...}`) before routing it back, and independently confirmed the fix by re-parsing the same file (`{'tags': ['maker', 'workflow', 'commitment', 'done'], ...}`) plus a from-scratch fixture proving tag-based scoring genuinely overrides filename tie-break (a lesson named to sort last alphabetically still ranked first once its tag matched the task).
  3. **(fork-found, between checker rounds):** the maker's own new regression test for finding #2 (`test_tag_scoring_beats_body`) passed vacuously — it searched the output for tag *values* ("specific"/"generic") that `build_output()` never actually prints (only lesson bodies are printed, never tags), so `output.find('specific')` always returned Python's `-1` "not found" sentinel, and `-1 < (any real index)` is unconditionally true regardless of whether tag scoring worked at all. The fork reproduced this directly before routing it back; fixed with unique body-text markers instead of tag values, explicit `>= 0` presence assertions, and filenames deliberately chosen so alphabetical tie-break would produce the *opposite* result if tag-scoring were broken.
  4. **(checker round 2, most severe test-hygiene finding):** the corrected `test_tag_scoring_beats_body` from fix #3 was itself never actually called anywhere in `selfcheck()`'s test sequence — genuinely dead code despite being well-constructed. The fork's own earlier mutation-test of fix #2 had "passed" only because a *different*, unrelated assertion (in `test_real_seed_files`) happened to also break from the same reverted mutation — masking that the specifically-requested test never ran even once. Fixed by adding the missing call; the fork re-mutation-tested specifically this time and confirmed the failure now genuinely originates from `test_tag_scoring_beats_body`'s own assertion line, not a coincidental neighbor.
  5. **(checker round 2, same round):** `README.md`'s manual "verify everything" chain was missing `bin/lesson-lookup.py selfcheck` entirely, despite this repo's own CLAUDE.md doc-sync convention requiring every new `bin/` script to be added there. Fixed.
  6. **Checker round 3: clean pass, zero findings**, after independently re-deriving via direct AST call-inspection that every defined `test_*` helper is genuinely invoked, independently mutation-testing the tag-scoring path itself (confirmed it fails specifically at `test_tag_scoring_beats_body`, not a neighbor), and independently confirming all 7 SKILL.md substitutions parse via `bash -n`.

- **Lesson:** the single most valuable pattern this task repeated three separate times was a test that *looks* rigorous but passes for the wrong reason — a broken bash substitution masked by nothing (pure syntax), a broken assertion masked by searching for text that's never actually printed, and a *correct* assertion masked by simply never being called. Each was caught only because the fork independently re-executed the real code path (a live substitution, a live parse, a live mutation-and-restore against the actual selfcheck) rather than trusting that a well-worded test with the right shape was doing what its name claimed. The fix for the second occurrence (dead-code test) was found by direct grep/AST inspection comparing every `def test_*` against every `test_*()` call — a cheap, mechanical check worth doing by default whenever a maker adds a new selfcheck assertion in the same round it also touches the test-runner's own call sequence.
