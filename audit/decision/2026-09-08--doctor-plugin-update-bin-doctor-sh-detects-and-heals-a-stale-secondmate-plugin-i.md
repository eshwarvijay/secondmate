## 2026-09-08 — doctor-plugin-update: bin/doctor.sh detects and heals a stale secondmate plugin install

- **Maker (pi/Qwen3-Coder-Next, medium thinking):** implemented the 5-state detection state machine, the heal action's safety-checked pull+update+verify, and a mkdir-based concurrent-heal lock, all per a plan-committee-authored spec (full adhd + 6-model plan-committee.sh run for this task per explicit user instruction). Required an unusually long tail of rounds — see flow.md for the full round-by-round breakdown.
- **Decisions:** (1) a discarded first attempt tried to combine "redesign the state machine" and "build the full selfcheck harness" into one round — abandoned after it degraded the maker's context and caused a real accidental corruption of the repo's own `plugin.json`; every subsequent round was deliberately scoped to one narrow fix or one narrow test addition at a time, restarting the maker with a fresh context at the start of nearly every round; (2) when a maker got stuck in a genuine repeated-retry loop against `scope-guard`'s worktree confinement (trying identical blocked `/tmp` script invocations many times), the supervisor's resolution both times was to redirect the maker toward using its own edit tool directly rather than any external script file, and once to hand over exact verbatim code for the maker to insert rather than another abstract instruction — matching the `doctor-version-flag` precedent for a maker stuck in a loop; (3) accepted one `[SUSPECTED]` (not confirmed) limitation from the final checker round — synthetic dead-PID lock fixtures using large hardcoded PID numbers that could theoretically, very rarely, collide with a real live process — documented rather than chased further, matching this repo's existing tolerance for narrow PID/TOCTOU risk elsewhere (`caffeinate-guard.sh`).
- **Checker findings resolved, most severe first (all real, all independently reproduced and fixed across 10 checker rounds):**
  1. **State-machine reference-version bug (round 1):** stale-vs-silent_drift compared `running_version` against `marketplace_version` instead of `installed_version` against `marketplace_version` — a real, healable version bump could be misreported as unhealable "silent drift" whenever the running script's own version happened to coincide with the marketplace's. Fixed to use `installed_version` (extracted fresh from `installed_plugins.json`) as the reference point in both `_detect_secondmate_status` and `_heal_secondmate`'s own skip-check, which had the identical bug independently.
  2. **Weak heal verification (round 1):** only checked "did the SHA change at all," accepting any wrong SHA (e.g. from a corrupt or buggy `claude plugin update`) as a successful heal. Fixed to require the post-update SHA equal the actual fetched remote SHA.
  3. **Unreachable stale-lock recovery (round 1) → real demonstrated TOCTOU race (round 2):** the original stale-lock-steal code was structurally unreachable for the realistic "lock already existed when first checked" case. The fix for that was itself proven racy by the checker's own orchestrated probe (a delayed `rm -rf`, based on a stale staleness-decision, destroying a different process's already-replaced fresh lock) — closed for real with an atomic `mv`-based claim plus post-claim re-verification, not another narrowing re-check.
  4. **A failed heal silently reported as script success (round 2):** `heal()`'s own captured failure was never checked, and the script's unconditional final exit-code line was unrelated to heal outcome regardless. Fixed by capturing the real exit code in the `--heal` dispatch branch and calling `exit` on it directly, bypassing the always-overriding final line — plus a genuine bash gotcha found independently by both the supervisor (mutation testing) and the maker (own tracing) in the same round: `[ "$heal_failed" -eq 1 ] && return 1` as a function's last line returns the `[ ]` test's own exit status when false, inverting success into failure on every call regardless of `$heal_failed`'s actual value.
  5. **The same "optimistic reporting on unverifiable/hard-abort state" bug class, independently found 4 more times across rounds 3-6:** the report table showing `[ok]`/plain "STATUS: ready" for a genuinely `stale` row (only `MISSING` was ever counted toward the summary); the identical gap for a malformed/unparseable `installed_plugins.json` (`UNKNOWN` state); `heal()` never dispatching to `_heal_secondmate` at all for a `missing` marketplace checkout (the spec's required hard-abort silently never fired); and the same STATUS-line gap recurring a third time specifically for the missing-marketplace row. Each instance found by a different checker round reviewing a different code path; each fix mirrored the pattern already established for the earlier instances (a dedicated counter, wired into the STATUS line's precedence chain).
  6. **Two already-correct hard-abort paths with zero regression coverage (round 7):** `git fetch` failure and `claude plugin update` failure were both already handled correctly in production code (independently verified by the supervisor with real fixtures before authorizing any change) but had never been exercised by a dedicated test. Test-only additions, no production change.
  7. **A genuine process-hygiene bug, found by the supervisor directly (not a checker round):** an early test's live-PID fixture spawned a real background `sleep 300` and never killed it, leaking a 5-minute orphaned process on every single selfcheck run — the actual root cause of a long string of apparent multi-minute "hangs" throughout this task (every one of which was a downstream pipe waiting for EOF that an orphaned process's inherited file descriptor kept open, never an actual hang in `doctor.sh` itself). Diagnosed via direct `ps aux`/`lsof` inspection while a maker's own piped invocation sat blocked.
  8. **Post-first-merge-only bug (round 9, after an initial genuine pass in round 8):** merging to main and bumping `plugin.json`'s version per this repo's standing convention immediately broke `doctor.sh --selfcheck`, because 5 selfcheck tests hardcoded `"0.1.8"` to mean "the currently running version" — invisible for the entire rest of the task only because this worktree's own version never itself changed across 18 rounds. The merge was cleanly unwound (nothing had been pushed) and redone once the fix (derive all such literals from the live `$version_line`) was verified directly against the actual post-bump failure. A second, one-level-deeper instance of the identical collision class (a hardcoded "must differ from running" literal that could itself coincide with a future real version) was found and closed the same way in round 9's own fix; round 10 returned a genuine pass.
