## 2026-09-10 — claim-ledger: atomic task-id claims, primitive 1 of 3 toward a future multi-supervisor dispatch loop

- **Maker (pi + Claude Sonnet 5, high thinking):** implemented `bin/claim-ledger.py` — an append-only JSONL ledger (hold.py's exact `_ledger_lock()` fcntl idiom) with `claim`/`release`/`steal`/`status`/`selfcheck` subcommands, a git-common-dir-anchored default path, and token-based ownership enforcement on `release`. Required 5 real fix rounds across 4 real checker rounds (a genuine cross-model `gpt` checker, retroactively engaged from round 3 onward after a process gap — see below).
- **Decisions:** (1) deliberately NO PID/process-liveness checking anywhere in the script — resolved via a full adhd ideation pass specifically on this question; the conclusion was that a claim ledger coordinating OTHER processes genuinely needs some liveness signal to scale past a handful of concurrent tasks (unlike caffeinate-guard's own simplification, which describes the supervisor's OWN self-observable process), but that THIS script isn't the right place for that oracle since real sub-agent runtimes (herdr agents, Agent-tool background agents) already track their own liveness in ways this generic CLI can't see anyway — `--steal --reason` is the entire human-triggered reclaim mechanism, full stop; (2) claim key is task-id, not worktree path, matching this repo's own established 1:1 task-id:worktree:branch convention throughout its history; (3) no compaction/rotation strategy, no SQLite, no new dependencies — stdlib + JSONL + fcntl only, matching hold.py's own precedent exactly.

- **Checker findings resolved, most severe first (all real, all independently reproduced by the supervisor before being routed to the maker):**
  1. **Label-only ownership, no real enforcement** (checker round 1): `--owner` was a caller-controlled string with no proof requirement — anyone repeating another owner's label could `release` their claim without going through the audited `--steal` override. Fixed with a `secrets.token_hex(16)` minted by `claim`/`steal`, required (with `--owner`) on `release`, never printed by `status`.
  2. **CWD-relative default ledger defeating the entire cross-worktree purpose** (checker round 1, same round): every herdr-launched sub-agent runs with its CWD set to its OWN worktree, so two supervisors in two different worktrees both "succeeded" at claiming the same task-id via two separate, unshared default ledgers. Fixed by anchoring to `git rev-parse --git-common-dir`'s parent (reusing `bin/mark-maker.sh`'s own primary-vs-worktree distinction mechanism).
  3. **Bare-repo and (later) submodule collisions on that same anchoring fix** (checker rounds 2-3): a bare repo's common-dir resolves to `.` (itself, not a `.git` subdirectory) and a submodule's common-dir's basename is its own name — taking the PARENT in either case (as the normal-repo rule does) collided sibling bare repos or sibling submodules onto the same arbitrary parent directory. Closed for real only once generalized to one rule: anchor at the parent ONLY when common-dir's own basename is literally `.git`; anchor AT common-dir itself in every other case — covering bare repos and submodules with a single check, removing an earlier separate `--is-bare-repository` special case entirely.
  4. **Wedged/unwedgeable malformed-token records** (checker rounds 2-3): a tokenless claimed/stolen record was accepted as open but could never be released (no caller can supply a token matching a missing field); a NUL-byte token is a non-empty string so it passed a naive "non-empty" check but no real CLI argv can ever contain an embedded NUL byte, so it was equally unwedgeable. Closed for real only once token validity was tightened to the EXACT `secrets.token_hex(16)` shape (`^[0-9a-f]{32}$`), not mere non-emptiness.
  5. **A leftover, self-diagnosed mutation-testing artifact** (supervisor's own pre-checker review): `steal()` folded the ledger BEFORE acquiring the lock — the maker's own code literally carried a `# MUTATION:` comment marking exactly this defect, evidence it was found and tested during the maker's own process but never reverted before committing. The existing "TOCTOU guard" selfcheck test didn't catch it because it wrote the competing ledger record directly to the file before ever calling `steal`, with nothing running concurrently to force a real race. Fixed by moving the fold inside the lock and replacing the fake test with a genuinely forced background-thread race.
  6. **Checker round 4: clean pass, zero findings**, explicit confirmation of no newly identified failure.
