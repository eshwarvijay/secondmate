## 2026-09-10 — merge-sequencer: serialize concurrent merges to main, primitive 2 of 3 toward a future multi-supervisor dispatch loop

- **Maker (pi + Claude Sonnet 5, high thinking):** implemented `bin/merge-sequencer.sh` — a singleton mkdir lock wrapping an unmodified `bin/verify-gate.sh` call, plus a closed-enum JSONL ledger, both anchored to `--repo`. Required 7 real fix rounds across 6 real checker rounds — the longest single-file checker loop in this repo's history to date, run in parallel with the sibling `claim-ledger` task the entire way through (see that task's own decision.md entry for the shared plan-committee background and the process gap both tasks shared).
- **Decisions:** (1) `bin/verify-gate.sh` is never modified — confirmed by reading its actual code that its `--base` resolution is already fresh at call time for this repo's real topology, independently corroborated by an adhd ideation pass that converged on the identical structural point unprompted; this kept the entire task scoped to wrapping/re-invoking rather than duplicating verify-gate's own checks; (2) no internal auto-retry on any failure, no priority queue/fairness policy, no automatic stale-lock expiry — matching the sibling `claim-ledger` task's identical scope philosophy and this repo's own established caffeinate-guard precedent (a human notices and manually clears a stuck lock; the script never guesses); (3) single machine only, no remote ref-based CAS — this repo's real topology is one local `.git` shared by the primary checkout and every worktree, so local operations inside one lock are sufficient.
- **Checker findings resolved, most severe first (all real, all independently reproduced by the supervisor before being routed to the maker):**
  1. **An independent/stale clone silently bypassing the entire freshness guarantee** (checker round 4): `--worktree` was only checked for existence, never validated as an ACTUAL linked worktree of `--repo`. A stale clone's own local `main` (frozen since it last fetched) could pass verify-gate.sh's freshness check against ITS OWN outdated state while the real merge landed into `--repo`'s genuinely newer, different state — commit SHAs being portable across clones is exactly what let the `--checked-sha` equality check pass despite the worktree being entirely unrelated. Fixed with a `git-common-dir` equality check, resolved via physical-path (`pwd -P`) comparison specifically to avoid a real macOS `/tmp`→`/private/tmp` symlink false-positive the maker discovered and preemptively fixed mid-round, without being asked to.
  2. **`--branch` never validated against the actually-reviewed commit** (checker round 1): verify-gate.sh only confirms `--worktree`'s own HEAD matches `--checked-sha` — the script then merged whatever `--branch` string was passed with no check it was the SAME commit. An entirely separate, never-reviewed branch could be named and merged instead of the reviewed one. Fixed with a `BRANCH_MISMATCH` reason code requiring exact resolution equality.
  3. **`git merge --abort` destroying a pre-existing, unrelated conflict this invocation never started** (checker round 1, same round): a human's own in-progress, unresolved merge conflict on `$repo` — sitting there before this invocation even began — was unconditionally classified identically to a fresh conflict and aborted, destroying state that was never this script's to touch. Fixed by detecting an existing `MERGE_HEAD`/dirty state BEFORE attempting any merge, refusing without ever calling `--abort` in that case.
  4. **A self-inflicted regression cascade on the script's own dirty-check exclusion** (checker rounds 3→5, three sequential findings on the SAME underlying mechanism): the script's own lock directory tripped its own newly-added dirty-repo guard on every default invocation (fixed with a basename-based pathspec exclusion) — which the very next round found was simultaneously too broad (swallowing a genuinely dirty unrelated file sharing that basename) AND incomplete (the ledger's own path was never excluded at all, breaking the script on its own second use). Properly closed only once basename matching was abandoned entirely for an exact-relative-path helper, discovering along the way that an out-of-repo literal pathspec fatally errors rather than harmlessly no-op-ing.
  5. **A real content conflict misclassified identically to a policy-hook rejection** (checker round 5): any `git merge` failure was reported as `MERGE_CONFLICT`, but a `pre-merge-commit` policy hook (a legitimate, common real-world mechanism) can reject a merge with zero actual content conflict — misleading the entire point of the closed-enum ledger design, since a human/dispatcher would reach for the wrong remediation. Fixed with a new `MERGE_REJECTED` code, distinguished via `git ls-files -u` captured before the cleanup `--abort` erases the evidence.
  6. **`PUSH_FAILED` had zero automated regression coverage** (checker round 3) despite the checker independently confirming the actual behavior was already correct via a manual rejecting `pre-receive` hook — closed with a real selfcheck test using the same technique.
  7. **Checker round 6: clean pass, zero findings**, explicit "ship recommendation: ship" after being directly asked to hunt for a sibling instance of finding #5's own bug class (two different failure causes folded into one reason code) elsewhere in the diff.
